# 状态码总览

> 本页汇总 Conrogate 全部业务错误码与相关 HTTP 状态码，覆盖控制面统一信封与数据面直接响应。**权威定义**：所有错误码以 `ConrogateError::ERR_*` 关联常量集中在 `conrogate-core/src/contract/error.rs`（`code()` 引用常量，控制面/数据面/插件均引用常量，禁止散落字面量）；统一响应信封/`error_body` 见 `conrogate-core/src/contract/response.rs`，数据面错误响应见 `conrogate-core/src/gateway/server.rs`（`error_response`）。

## 1. 响应信封

所有接口（控制面 API / 数据面网关错误）返回统一 JSON 结构：

```json
{
  "code": 10004,
  "msg": "资源不存在: route: not found",
  "data": null,
  "trace_id": "000000000000000018c993af222b3850"
}
```

| 字段      | 说明                                              |
|-----------|---------------------------------------------------|
| `code`    | 业务错误码。`0` = 成功，非零 = 错误（见下表）     |
| `msg`     | 错误描述（内部错误统一为 `internal error`，不透出细节） |
| `data`    | 成功时为业务数据，失败为 `null`                   |
| `trace_id`| 本次请求追踪 ID，便于日志/审计串联                |

> 数据面黑名单/插件拦截的响应体精简为 `{"code":...,"msg":...}`（无信封，见 §4）。

## 2. 分段总览

| 段      | 归属        | 含义                                             |
|---------|-------------|--------------------------------------------------|
| `0`     | 通用        | 成功                                             |
| `1xxxx` | 通用        | 客户端/业务参数、鉴权、资源通用错误              |
| `2xxxx` | 配置/路由   | 路由、上游、插件、配置版本相关错误               |
| `3xxxx` | 数据层      | 数据库访问 / 数据转换 / 迁移错误                 |
| `4xxxx` | 网关转发    | 数据面转发链路错误（上游/限流/熔断/协议）        |
| `5xxxx` | 系统        | 配置加载、初始化、就绪探针等系统级状态           |

## 3. 完整错误码表

### 1xxxx 通用（`0` = 成功）

| 错误码 | HTTP 状态码 | 说明                                        | 典型 `msg` 示例 |
|--------|-------------|---------------------------------------------|-----------------|
| `0`    | `200`       | 成功                                        | `success`       |
| `10001`| `200`       | 请求参数非法                                | `参数非法: 非法 IP 或 CIDR: not-an-ip` |
| `10002`| `401`       | 未认证（缺少/无效 Token，或 JWT 校验失败）  | `unauthorized` / `unauthorized: invalid token` |
| `10003`| `200` / `403`| 权限不足（控制面 RBAC）或 IP 被拒绝（数据面，见 §4） | `无权限` / `forbidden: ip not allowed` |
| `10004`| `200`       | 资源不存在                                  | `资源不存在: blacklist entry not found` |
| `10005`| `200`       | 资源冲突（重复创建/命名冲突）               | `资源已存在: ...` |
| `10006`| `200`       | 请求过于频繁（限流，控制面）                | `请求过于频繁`   |
| `10007`| `200` / `413`| 请求体过大                                  | `请求体过大` / `request body too large` |
| `10008`| `400`       | 请求体读取失败（数据面缓冲模式）            | `request body read error: ...` |
| `10009`| `408`       | 请求体读取超时（数据面缓冲模式）            | `request body read timeout` |

> `1xxxx` 段另支持 `Business { code, message }` 动态业务错误，`code` 由业务方自定义。

### 2xxxx 配置 / 路由

| 错误码 | HTTP 状态码 | 说明                       |
|--------|-------------|----------------------------|
| `20001`| `200`       | 路由不存在                 |
| `20002`| `200`       | 上游不存在                 |
| `20003`| `200`       | 插件配置非法               |
| `20004`| `200`       | 插件未找到                 |
| `20005`| `200`       | 插件运行时异常             |
| `20006`| `200`       | 配置校验失败               |
| `20007`| `200`       | 配置发布并发冲突           |

### 3xxxx 数据层

| 错误码 | HTTP 状态码 | 说明           |
|--------|-------------|----------------|
| `30001`| `500`       | 数据库错误     |
| `30002`| `500`       | 数据转换错误   |
| `30003`| `500`       | 数据库迁移错误 |

> `3xxxx` 均为内部错误，对外 `msg` 固定为 `internal error`。

### 4xxxx 网关转发（数据面）

| 错误码 | HTTP 状态码 | 说明                       |
|--------|-------------|----------------------------|
| `40001`| `500`       | 网络/代理内部错误          |
| `40002`| `502`       | 上游连接超时               |
| `40003`| `502`       | 上游连接失败               |
| `40004`| `502`       | 上游响应异常               |
| `40005`| `200`       | 协议不支持                 |
| `40006`| `502`       | 网关内部错误（兜底，含路由未命中）|
| `40007`| `503`       | 服务熔断中                 |
| `40008`| `429`       | 请求被限流拦截             |
| `40009`| `502`       | 请求重试耗尽               |

> `40002`/`40003`/`40004` 在上游链路中最终由数据面映射为 `502 + 40006`（网关错误兜底），控制面直接返回时仍为各自错误码。

### 5xxxx 系统

| 错误码 | HTTP 状态码 | 说明                                  |
|--------|-------------|---------------------------------------|
| `50001`| `500` / `503`| 配置加载失败；就绪探针 `GET /readyz` 在路由为空时返回 `503` |
| `50002`| `500`       | 初始化失败                            |
| `59999`| `500`       | 内部错误（兜底）                      |

## 4. 数据面直接响应（HTTP / WS / TCP）

数据面在**路由匹配前 / 协议层**直接拦截时，不经过统一信封，精简响应体为：

```json
{"code": 10003, "msg": "forbidden: ip not allowed"}
```

| 场景                          | HTTP 状态码 | 错误码 | 响应体 `msg` |
|-------------------------------|-------------|--------|--------------|
| 全局 IP 黑名单命中（HTTP/WS） | `403`       | `10003`| `forbidden: ip not allowed` |
| `ip_allow_deny` 插件拒绝      | `403`       | `10003`| `forbidden: ip not allowed` |
| Auth 插件校验失败             | `401`       | `10002`| `unauthorized: <原因>` |
| 全局 IP 黑名单命中（TCP 隧道）| 连接断开    | -      | -            |
| 路由未命中                    | `502`       | `40006`| `gateway error` |
| 请求体过大                    | `413`       | `10007`| `request body too large` |
| 请求体读取失败                | `400`       | `10008`| `request body read error: ...` |
| 请求体读取超时                | `408`       | `10009`| `request body read timeout` |
| 限流拦截                      | `429`       | `40008`| `rate limited` |
| 熔断打开                      | `503`       | `40007`| `circuit breaker open` |
| 就绪探针（路由为空）          | `503`       | `50001`| `not ready: no routes loaded` |

## 5. 注意事项

- **HTTP 状态码约定**：控制面业务错误除 `401`（未认证）与 `500`（内部错误）外一律 `200`，靠 `code` 区分；数据面错误按上表映射（`502`/`429`/`503`/`413`/`408`/`400`/`403`/`401`）。
- **`10003` 双重含义**：控制面 = RBAC 权限不足；数据面 = IP 被黑名单/`ip_allow_deny` 拒绝。判断依据来源端点（控制面走信封，数据面走精简体）。
- **内部错误不外泄**：`3xxxx`、`40001`、`40006`、`5xxxx` 等内部错误对外固定返回 `internal error`，`trace_id` 用于日志排查。
- **健康/就绪探针**：`GET /healthz` → `200`，`GET /readyz` → `200 ready`（路由非空）或 `503`（路由为空，错误码 `50001`）。
